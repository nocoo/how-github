# 13 · 杰文斯悖论：AI 让代码变便宜，GitHub 会更值钱吗？

> 更新：2026-11-09（北京时间）｜ 第二期补充 ｜ 标注规则同 [README](README.md)，【X】= X 公开帖子。

## 1. 概念

1865 年经济学家 William Stanley Jevons 观察到：蒸汽机燃煤效率大幅提升后，英国的煤炭消耗**不降反升**。推广到软件：**当 AI 把“写一行代码”的边际成本压到接近零，社会对代码的总需求可能反而暴增**——更多项目、更多仓库、更多 PR、更多 CI 分钟。

成立的前提有两个：① 需求对价格**高度弹性**（便宜了就会做以前不值得做的项目）；② 下游环节（审查、部署、维护）**不成为硬瓶颈**。

## 5. 对 GitHub 的含义：谁吃到悖论的红利？

| 收入线 | 计费单位 | 杰文斯效应 | 判断【推断】 |
|---|---|---|---|
| Copilot（AI Credits） | token / credit | **正**：用量与代理数正相关 | 量增但毛利取决于模型成本；GitHub 是“转售商”，议价权在模型厂商 |
| Actions / Codespaces | 分钟、核时 | **强正**：代理 PR 都要跑 CI | 最纯粹的受益者；但也是故障重灾区 |
| GHAS（Secret Protection / Code Security） | 活跃提交者 | **正**：代码越多风险越多；代理是否算“提交者”会决定天花板 | 最清晰的变现 |
| 平台席位（Team/Enterprise） | 人头 | **弱/负**：如果“一人 + N 代理”替代团队，席位增长放缓 | 长期压力 |
| 存储（LFS/Packages） | GB、流量 | 正 | 量小 |

**核心判断**【推断】：
1. 杰文斯悖论在 GitHub 的**活动量**上已经被验证（写入量 2 年 3 倍），但在**收入与利润**上尚未被验证——GitHub 2024-07 之后不再披露美元收入。
2. 悖论的真正赢家是**按量计费、且边际成本低**的环节（Actions 自托管、安全扫描、审查编排），而不是“替别人卖 token”的 Copilot。
3. 悖论有一个**内生的刹车**：人类审查带宽和开源维护者的耐心。GitHub 的产品路线（PR 限额、关闭 PR 开关、代理审查）本质上是在给这个刹车装“助力器”。
4. 对中国开发者而言，悖论表现为“**开源模型 + 低价 token → 更多开源仓库 → 更多 GitHub 曝光**”的正循环（见 [14](14-中国开发者与GitHub-X舆情.md)）。

## 6. 可以证伪的观察指标

| 指标 | 悖论成立的信号 | 悖论失效的信号 |
|---|---|---|
| Octoverse 2027 的 push/commit/PR | 继续 2 倍以上增长 | 增速回落到 20–30% |
| 代理 PR 合并率 | 维持 ≥ 人类 PR | 明显低于人类 PR（审查拒收） |
| 微软电话会 credit 消耗 | 连续环比翻倍 | 增速快速收敛 |
| Copilot 付费订阅 | 470 万继续高增长 | 被 Claude Code/Codex 替代 |
| 每活跃仓库的维护者数 | 稳定 | 维护者流失、仓库“僵尸化” |
| GitHub 可用性 | 迁移完成后故障下降 | 继续频繁故障（容量追不上需求） |
