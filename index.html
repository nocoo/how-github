02 / 演进路径

18 年，三次重心迁移。

从开源协作网络，到企业软件平台，
再到微软的 AI 软件交付入口。

2008 — 2017 开发者网络2018 — 2023 企业平台2024 — 2026 代理经济
2008

让代码协作变成一种网络

Chris Wanstrath、PJ Hyett、Tom Preston-Werner 与 Scott Chacon 创立 GitHub。围绕 Git，把代码托管、贡献记录与开发者身份连接起来。

商业意义 / 社区和协作关系先于商业化积累
2018

75 亿美元，进入微软版图

微软 6 月宣布以股票收购 GitHub，10 月完成交割，Nat Friedman 出任 CEO。宣布收购时，平台已有约 2,800 万开发者。

商业意义 / 接入企业渠道、云基础设施与资本
2020

收购 npm，把触角伸向软件供应链

npm 连接 JavaScript 的依赖生态；免费团队私有仓库降低协作门槛。GitHub 的边界从“代码存在哪里”扩展到“软件如何被构建”。

商业意义 / 免费协作扩大入口，供应链加深生态黏性
2022

Copilot 从技术预览走向收费

2021 年预览后，Copilot 在 2022 年 6 月向个人开放付费订阅，月费 10 美元。GitHub 开始从管理代码，进入辅助编写代码。

商业意义 / 在平台席位之外建立新的 AI 收费面
2025

更深地融入微软，向多代理平台转向

媒体报道 Thomas Dohmke 宣布离任，GitHub 并入 Jay Parikh 领导的 CoreAI。Agent HQ 推出，安全产品拆分销售，Azure 迁移进入关键阶段。

口径说明 / 组织变化含媒体信息；此后的独立 CEO 任命未核实
2026

从“多少人订阅”，到“代理完成多少工作”

6 月 Copilot 转向 AI Credits 按量计费；10 月发布 Copilot app、Fusion 与企业 Copilot access。软件交付闭环成为产品整合的中心。

商业意义 / 席位、模型用量、计算与治理形成混合收入模式

依据：公司概况与历史。早期事件沿用原资料，未在本次重新核实；商业意义为研究解读。

03 / 产品版图

不只是托管代码。
是一整条软件生产线。

从想法、开发、审查到部署，
免费入口与付费能力层层衔接。

计划 Issues · Projects编写 Copilot · Codespaces协作 Repositories · PR验证 Security · Review交付 Actions · Packages
12 项核心能力
01 / 协作底座

Repositories & PR

代码托管、版本管理、Pull Requests、代码审查与 Discussions。开发者身份和协作记录沉淀于此。

免费入口 → 高级协作席位
02 / 工作管理

Issues & Projects

连接需求、任务、里程碑与代码变更。Wiki 和 Pages 承载文档与静态站点。

平台黏性 → 团队升级
03 / 企业治理

GitHub Enterprise

Cloud 提供企业托管用户、数据驻留等云端治理；Server 满足自托管需求。身份与审计能力依部署方式而异。

按用户订阅 + 企业支持合同
04 / 自动化

GitHub Actions

CI/CD、测试、构建与部署。人类提交和代理产出都需要执行验证，形成持续计算需求。

托管 runner 分钟 + 存储
05 / 云开发

Codespaces

浏览器或本地编辑器连接云端容器环境，减少开发环境配置成本。

计算时长 + 存储
06 / 制品与运行

Packages · LFS · Sandbox

包、容器镜像、大文件与隔离执行环境。Sandbox 的正式发布时间在原资料中尚待核实。

存储 / 流量 / 计算用量
07 / AI 入口

GitHub Copilot

补全、Chat、CLI、云端代理、代码审查与桌面 app，覆盖从编辑器到 PR 的工作。

订阅 + AI Credits
08 / 代理平台

Agent HQ & Models

统一管理自营与第三方代理；GitHub Models 提供模型入口，Fusion 负责多模型编排。

模型用量 + 平台工作流
09 / 安全治理

Advanced Security

Secret Protection 防止密钥泄露；Code Security 集成 CodeQL、依赖审查与 Autofix。

活跃提交者订阅 + AI 用量
10 / 软件供应链

npm & Marketplace

npm 连接 JavaScript 包生态，Marketplace 连接 Apps 与 Actions，扩展平台能力与分发网络。

生态分发；Marketplace 分成待核实
11 / 开源资助

GitHub Sponsors

让个人和组织资助开源维护者。个人赞助零手续费，组织赞助存在手续费。

生态留存 + 部分交易手续费
12 / 人才入口

Education & Open Source

学生、教师、开源维护者的免费权益，让下一代开发者更早进入 GitHub 工作流。

获客与网络效应，非直接营收指标

产品与收费面：产品矩阵 · 定价研究。以上为业务分类，不是官方收入分部。第二期还讨论 Spark 的应用生成入口；GitHub Models 的模型调用能力，不等于 Hugging Face / ModelScope 的权重与数据集分发地位。三层竞争边界 ↗

收入底盘

卖协作与管理权

Team / Enterprise 平台席位、安全模块和企业支持，为组织提供规则、权限、审计和合规能力。

增长变量

卖执行与 AI 消耗

代理越活跃，模型推理、测试、审查和沙箱的消耗可能越大；但收入增长必须覆盖基础设施与推理成本。

长期护城河

让工作流留在平台

即便开发者使用别家的代理，PR、验证、安全和交付仍可能在 GitHub 上完成。工具竞争和平台收入并不完全重合。

商业逻辑为定性推断，依据：商业模式与生态布局。GitHub 未披露各业务收入占比。

09 / 六种平台角色

AI 代码需要地方存。
但“存”不是全部价值。

从落盘、执行到可信交付，
每一种角色都有资产，也有替代路径。

R1 / 记录系统

代码落盘点

Commit、push、merge 保存代码版本与变更历史。活动增长让可靠写入更重要。

边界 Git 是分布式的，托管可迁移；一次性仓库未必持续创造价值。
R2 / 代理控制面

任务与执行工作台

Issue 分配工作，PR 承载结果，Actions 运行验证。Agent HQ 接纳不同厂商的代理。

边界 Cursor Origin、OpenAI Pando 等正在争夺代理工作流的位置。
R3 / 历史知识

训练与评测材料

代码和 issue 积累真实软件问题。资料列举的原始 SWE-bench 含 12 个仓库的 2,294 道任务。

边界 历史材料价值不等于可直接变现；公开可见也不等于无限训练授权。
R4 / 网络效应

分发与声誉

Star、贡献记录、issue 与下游集成，让一个项目被发现，并建立持续协作关系。

边界 Star 不是质量评分。刷星与伪造历史会侵蚀信任，相关规模数字待核实。
R5 / 质量关口

审查与合并

PR 留下讨论、审查和批准记录，人类决定哪些变更能进入生产流程。

基线指数为 100，不是美元；单位成本为原来的 50% 时，使用量达到 2 倍，总支出才与基线相同。

可能放大的收入面

AI 与计算用量

Credits、托管 Actions、Codespaces 与存储可能随活动量增长，但单位价格、免费额度、合同折扣和边际成本共同决定结果。

不能直接放大的收入面

席位与活跃提交者

“一人 + 多代理”不等于更多人头。GHAS 主要按活跃提交者收费，GitHub App 机器人不计入；更多 PR 不会自动带来同比例安全收入。

需求的刹车

审查、质量与容量

维护者带宽、故障、一次性项目和用户预算都可能限制需求。自托管 runner 在资料时点仍免费，不能将其当作已收费的增长引擎。

观察到活动量增长，不等于完成了因果证明。

支出超过基线的条件是：单位成本比例 × 用量倍数 > 1。例如成本降至 50%、用量增至 1.5 倍，总支出仍只有基线的 75%。这个示例没有识别真实需求弹性，也未纳入固定成本。Nadella 的杰文斯悖论表述是管理层叙事；GitHub 的活动量增长与之相容，但不足以证明效率提升导致增长，更不能证明利润上升。

乐观 / 主观权重 30%

代理的默认交付平台

可靠性明显改善，Agent HQ 成为多代理工作台，企业用量增长能覆盖基础设施与推理成本。

要验证 迁移与存储能力真实上线、企业采用、交付质量，以及收入绝对值的重新披露。
基准 / 主观权重 50%

重要，但更像后台管道

开发者更多在别家的代理里工作，GitHub 仍承接 PR、CI 与安全。活动量可增长，议价权与利润率尚不确定。

要验证 任务是否继续留在 GitHub、客户是否愿意付费，以及每单位工作负载的成本。
悲观 / 主观权重 20%

入口与托管被一起带走

可靠性问题持续，代理厂商把模型、托管与部署捆绑。更多新项目选择别处，GitHub 依赖存量与开源长尾。

要验证 竞品是否公开产品化、迁移是否持续，以及新项目的真实首选平台。

用六组证据，而不是热度，更新判断

可靠性
按月看事故次数与时长、迁移进展；内测吞吐量不是 SLA。
托管竞争
看 Origin 的成熟度与 Pando 的公开产品化，而非只看公告。
商业兑现
看付费人数、credits 周期口径、美元收入与成本，避免混算日期。
交付质量
看 PR 审查等待、后续缺陷与维护者负担，不能只看合并率。
生态信任
区分迁出声明与完成迁移，追踪核心项目、数据政策与第三方待遇。
中国与全球分发
分别看可达性、贸易管制与地区服务政策、跨平台协作和项目采用，不用情绪样本估计市场份额。

5,000 个并发代理，不是每个仓库的服务承诺。
